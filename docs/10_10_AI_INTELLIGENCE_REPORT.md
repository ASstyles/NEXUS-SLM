## 2. The Clean-Data Revolution: Zero-Leakage Dataset Architecture

### 2.1 The Legacy Data Defect
In the original dataset, tickets were generated by permuting a fixed set of synthetic sentence frames across random user names, order IDs, and monetary amounts. When randomized 80/10/10 splits were created, identical sentence templates were distributed across both training and test sets. Consequently, previous models appeared to achieve artificially high accuracy while failing to generalize to unseen phrased tickets.

### 2.2 Template-Grouped Segregation (`data/v2_clean_template_grouped/`)
To establish a rigorous, realistic benchmark, the dataset was completely re-architected into template groups:
- **Train Split (`train_clean.jsonl`):** 4,797 records (79.0%)
- **Validation Split (`val_clean.jsonl`):** 449 records (7.5%)
- **Test Split (`test_clean.jsonl`):** 746 records (13.5%)
- **Total Volume:** 5,992 verified records spanning 14 support categories and 3 languages (English, Native Devanagari Hindi, and Latin-script Hinglish).

**Mathematical Invariant:**
$$\text{Templates}(\text{Train}) \cap \text{Templates}(\text{Val}) \cap \text{Templates}(\text{Test}) = \emptyset$$

No semantic sentence frame in the locked test set ever appears in the training or validation splits, ensuring that measured performance reflects true zero-shot semantic comprehension rather than rote template memorization.

## 3. Remote Cloud GPU LoRA Training Execution

Remote training was executed on Kaggle utilizing a free NVIDIA Tesla T4 GPU.

### 3.1 Hardware & Environment Configuration
- **Compute Instance:** Kaggle Container running Linux 6.18, Python 3.13.15, PyTorch 2.11.0+cu128.
- **GPU Accelerator:** **NVIDIA Tesla T4** (15,360 MiB GDDR6 VRAM, Compute Capability 7.5).
- **Precision:** Float16 / Bfloat16 mixed-precision acceleration.
- **Base Foundation Model:** `Qwen/Qwen2.5-0.5B-Instruct` (0.49B active parameters).

### 3.2 Hyperparameter & LoRA Architecture Specification
- **PEFT Method:** Low-Rank Adaptation (LoRA)
- **Rank ($r$):** 16
- **Scaling Factor ($\alpha$):** 32 ($\alpha/r = 2.0$)
- **LoRA Dropout:** 0.05
- **Target Projection Modules:** `q_proj`, `k_proj`, `v_proj`, `o_proj`, `gate_proj`, `up_proj`, `down_proj` (all self-attention and MLP feed-forward projections)
- **Trainable Parameters:** 9,240,576 parameters (~1.88% of total model capacity)
- **Optimization Strategy:**
  - Optimizer: AdamW (`weight_decay=0.01`, $\beta_1=0.9, \beta_2=0.999$)
  - Learning Rate: $2.0 \times 10^{-4}$ with Cosine Annealing decay
  - Warmup: 5% of total steps (60 steps)
  - Batch Size: 4 per device with Gradient Accumulation Steps = 2 (Effective Batch Size = 8)
  - Epochs: 2.0 (1,200 total optimization steps)
  - Loss Masking: Completion-only loss masking targeting exclusively JSON output tokens (ChatML prompt tokens masked to `-100`).

## 5. Multi-Tier Escalation Safeguards & Confidence Calibration

### 5.1 Deterministic Policy Dominance Invariant
To prevent catastrophic failure in critical enterprise workflows, NEXUS-SLM enforces a mathematical guarantee:
$$\text{requires\_human}_{\text{final}} = \text{requires\_human}_{\text{policy}} \lor \text{requires\_human}_{\text{model}} \lor (\text{confidence} < \tau)$$

Under no circumstances can a high model confidence override a deterministic policy rule. If a customer reports unauthorized charges, legal threats, account lockouts, or delivery tampering, the system routes the ticket to a human specialist with 100% recall.

### 5.2 Confidence Calibration & Selective Prediction (`src/models/calibration.py`)
- **`TemperatureScalingCalibrator`:** Softens uncalibrated logits using learned temperature parameter $T > 0$ via $\hat{p} = \sigma(\text{logit} / T)$.
- **`CalibrationEvaluator`:** Computes Expected Calibration Error (ECE) and Brier Score across probability bins.
- **`SelectivePredictor`:** Establishes risk-coverage routing with threshold $\tau = 0.85$. Tickets with calibrated confidence $\ge 0.85$ are eligible for automated straight-through resolution; all ambiguous or low-confidence tickets are routed to human review.

### 5.3 Adversarial Defense & Prompt Injection Detection
Tickets are screened in real-time by `inspect_prompt_injection()` for:
- Instruction overrides (`ignore previous instructions`, `disregard prior directives`).
- Delimiter escapes (`<|im_start|>`, `<|im_end|>`).
- Persona hijacking (`developer mode`, `dan mode`).
Attacks are flagged with `risk_level: critical` and forced into human investigation queues without contaminating training data or executing unauthorized system commands.
